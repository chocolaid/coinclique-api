# Group Management API Specification

## Overview
This API handles all group-related operations including creation, management, invites, policies, and member operations. It's designed to work with the CoinClique mobile app and handles Firebase authentication and Firestore operations server-side.

**IMPORTANT: This API is critical for the mobile app's group functionality. Every endpoint must handle financial transactions properly, update user wallets, and maintain transaction history. The mobile app will make simple HTTP requests and expect consistent responses.**

## Base URL
```
https://coinclique-api.vercel.app/api/groups
```

## Authentication
All endpoints require a valid Firebase ID token in the Authorization header:
```
Authorization: Bearer {firebase_id_token}
```

## Core Features & Business Logic

### Group Types & Auto-Save Rules
- **Strict Groups**: Users MUST have a saved card before joining. Card unlinking is blocked after joining.
- **Flexible Groups**: Users can contribute manually without saved cards.
- **Auto-save**: Only works for users with saved cards. Failed auto-saves trigger penalties.

### Financial Transaction Rules
- **Every financial operation** must update both user wallet and transaction history
- **Penalties**: Applied when users leave early or miss payments
- **Group dissolution**: Owner pays disbursement fees from their share
- **Negative balances**: Allowed when penalties exceed wallet balance

### Invite System
- **Invite codes**: Generated by group owners, can have expiry dates
- **Revocation**: Owners can revoke active invite codes
- **Auto-join**: Users get immediate access after valid invite code input

### 9. Leave Group
**POST** `/leave/{groupId}`

**Purpose**: Users leave groups voluntarily. Mobile app shows confirmation dialog and handles penalties.

**Response:**
```json
{
  "success": true,
  "message": "Successfully left group",
  "penaltyApplied": 5000,
  "refundAmount": 45000,
  "totalContributed": 50000
}
```

**Business Logic**:
- Check if user is group creator (cannot leave, must disband)
- Calculate penalties based on group policy
- Apply penalties to user's wallet (can go negative)
- Refund remaining contributions to user wallet
- Remove user from group members
- Update group status if below minimum members
- Send system message: "User left the group (penalty: ₦X)"
- Create transaction records for penalty and refund
- Update group current amount

### 10. Delete Group (Disband)
**DELETE** `/delete/{groupId}`

**Purpose**: Group owner disbands the group. Mobile app shows confirmation and handles fund distribution.

**Response:**
```json
{
  "success": true,
  "message": "Group disbanded successfully",
  "disbursementFee": 2500,
  "totalDistributed": 97500,
  "membersRefunded": 3
}
```

**Business Logic**:
- Verify user is group creator
- Calculate disbursement fee (owner pays this)
- Distribute remaining funds to all members proportionally
- Update each member's wallet balance
- Create transaction records for all disbursements
- Send system message: "Group has been disbanded. Funds distributed to members."
- Update group status to "disbanded"
- Archive group data (don't delete completely)
- Owner's share is reduced by disbursement fee

## Error Responses

All endpoints return consistent error responses:

```json
{
  "success": false,
  "error": "Error message",
  "code": "ERROR_CODE"
}
```

**Common Error Codes:**
- `INVALID_TOKEN`: Invalid or expired Firebase token
- `GROUP_NOT_FOUND`: Group doesn't exist
- `INSUFFICIENT_PERMISSIONS`: User doesn't have permission for this action
- `INVALID_INVITE_CODE`: Invalid or expired invite code
- `GROUP_FULL`: Group has reached maximum member limit
- `ALREADY_MEMBER`: User is already a member of the group
- `INVALID_POLICY`: Invalid policy configuration
- `GROUP_ACTIVE`: Cannot perform action on active group

### Financial Transaction Flow
1. **Every operation** that moves money must:
   - Update user wallet balance
   - Create transaction record in `transactions` collection
   - Update group current amount
   - Send system message to group chat
   - Update group status if needed

2. **Transaction Types**:
   - `group_contribution`: User contributes to group
   - `group_penalty`: Penalty applied for leaving/missing payment
   - `group_refund`: Refund when leaving/disbanding
   - `group_disbursement`: Final distribution when disbanding
   - `penalty_application`: Penalty applied for rule violations
   - `chat_system_message`: System message sent to group chat

3. **Wallet Updates**:
   - Use Firestore transactions to prevent race conditions
   - Allow negative balances for penalties
   - Update both `wallet.balance` and `wallet.locked` fields

### Data Validation
1. **Group Names**: 3-50 characters, alphanumeric + spaces
2. **Goal Amounts**: 1000-10,000,000 NGN
3. **Member Limits**: 2-20 members
4. **Phone Numbers**: Nigerian format validation

### Business Logic
1. **Group Status Management**: Automatic status updates based on member count and activity
2. **Policy Enforcement**: Apply penalties and bonuses according to group policies
3. **Auto-save**: Handle automatic contributions based on frequency settings
4. **Member Management**: Handle join/leave with proper fund distribution logic

### Critical Business Rules
1. **Strict Groups**: Users cannot join without saved card, cannot unlink card after joining
2. **Penalties**: Applied immediately when users leave or miss payments
3. **Auto-save Failures**: Trigger penalties and system messages
4. **Group Dissolution**: Owner pays all fees, members get proportional refunds
5. **Negative Balances**: Allowed for penalties, users must top up to continue using app
6. **System Messages**: Every financial action generates a chat message for transparency

### Security Considerations
1. **Rate Limiting**: Prevent abuse of invite generation and joining
2. **Input Sanitization**: Sanitize all user inputs
3. **Permission Checks**: Verify user permissions for each operation
4. **Audit Logging**: Log all group operations for security

### Performance Optimization
1. **Caching**: Cache frequently accessed group data
